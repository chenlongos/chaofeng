### 2.2 AKA-00 机器人参考架构分析

深度分析了 chenlongos/AKA-00（299元开源捡球机器人，北京 AI 原点社区明星项目）的完整技术栈：

- **硬件架构**：SG2002 + ESP32-C3（底盘 PWM PID） + ZP10S/STS3215 舵机（UART）
- **控制算法**：5 状态 FSM（chase→position→grab→bucket→release）+ P 比例差速控制
- **通信协议**：ESP32 UART 帧协议（0xAA 0x55 + checksum），ZP10S ASCII 协议
- **Web 前端**：React + TypeScript，支持方向键/RC 摇杆/重力感应/模型商店

## 五、关键技术细节

### 5.1 YUYV 直通管线

区别于 AKA-00 的 OpenCV BGR 路径（需 JPEG 解码 + 色彩空间转换），我们实现了 YUYV native 管线：

- 摄像头输出的 YUYV 422 原始帧直接送 C 预处理
- C 预处理一次完成 YUYV→RGB→resize→CHW planar，零零拷贝写入 TPU 输入 buffer
- 精度更高：检出置信度 0.95-0.97 vs OpenCV 路径的 0.85

### 5.2 StarryOS vs AKA-00 Linux 对比

| 维度 | 我们的方案 (StarryOS) | AKA-00 (Buildroot Linux) |

### 5.3 ESP32-C3 电机控制协议

TT 马达通过 ESP32-C3 UART 接收 PWM 指令，帧格式：`0xAA 0x55 <CMD> <LEN> <payload> <CHK>`。关键指令：

- `0x13 SET_SPEEDS`: 双电机差速控制（-100~100 PWM%）
- `0x12 BRAKE`: 双电机刹车
- `0x11 STOP`: 滑行停止
- `0x21 GET_STATUS`: 读取 RPM

ESP32 固件在微控制器侧执行 PID 闭环，SG2002 只需下发目标速度，实时控制解耦。

### 5.4 预处理 6 轮优化总结

| 版本 | 方案 | 耗时 | 备注 |
|------|------|------|------|
| v1 | 有 malloc 分离版 | 235ms | 基线 |
| v2 | 融合版，消除 malloc | 143ms | 质的飞跃 |
| v3 | 双线程 | 216ms | GIL 争抢，无效 |
| v4 | 定点数 | 171ms | FPU 比定点快 |
| v5 | 回到浮点 | 143ms | 与 v2 持平 |
| v6 | 直写 TPU buffer | 143ms | 零拷贝，当前版本 |

结论：143ms 为纯 C 在 SG2002 1GHz C906 上的极限，进一步优化需要 ARM 向量化或 DMA。
